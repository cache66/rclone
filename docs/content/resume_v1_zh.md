# Resume V1 使用说明（copy 断点续跑）

## 功能简介

Resume V1 用于 `copy` 任务的断点续跑。

当扫描或传输过程中断后，下次重新执行 `copy` 命令时，可以从上次记录的位置继续处理，而不是从头开始。

这个能力适合以下场景：

- 长时间迁移任务中途被中断
- 任务进程退出后需要继续执行
- 希望保留已经完成的迁移结果，不重复传输

## 当前支持范围

当前版本只支持 `copy`，不支持 `check`、`move` 或带删除语义的 `sync`。

当前支持以下源类型：

- 文件系统源
- S3 源

只要源端支持重新扫描或继续列举目录，resume 就可以继续工作。目标端不要求具备专门的 resume 能力。

## 中断后会恢复什么

任务重启后，resume 会恢复以下状态：

- 扫描游标：从上次扫描到的位置继续
- 已完成文件记录：已经成功迁移的文件不会重复传输
- 累计统计：已迁移文件数、已迁移字节数
- 失败状态：失败文件数量、失败记录，并在下次启动时优先重试

对两类常见源的处理方式如下：

### 文件系统源

文件系统源会重新列目录，然后根据已完成记录跳过已经迁移成功的文件，从上次位置继续往后处理。

### S3 源

S3 源优先使用分页 continuation token 从上次列举位置继续。如果 token 不可用，也可以退回到重新列举并跳过已完成文件的方式继续执行。

## 当前不支持的内容

当前版本不支持以下能力：

- `check` 的断点续跑
- `move` 的断点续跑
- `sync` 删除阶段的断点续跑
- 单个大文件传输到一半后的字节级续传

也就是说，如果某个大文件在传输过程中断，下次会重新传输这个文件；但已经成功完成的其他文件会被跳过。

## 关于重启后的校验

Resume V1 不会在任务重启后先做一轮全量 `check`。

默认前提是迁移源不会发生变化。在这个前提下，系统直接从上次位置继续执行，而不是重新全盘校验已完成文件。这样可以减少重启后的额外耗时。

如果源端在中断期间发生变化，当前版本不保证结果正确性。

## 基本使用方式

### 直接开启 resume

```bash
rclone copy /data/source remote:backup --resume
```

### 指定 resume 任务 ID

```bash
rclone copy /data/source remote:backup --resume --resume-id job-001
```

如果不指定 `--resume-id`，系统会根据命令和远端自动派生一个任务 ID。

### 限制失败文件数量

```bash
rclone copy /data/source remote:backup --resume --resume-error-limit 100
```

当待处理的失败文件数量超过上限时，当前任务会停止，并保留状态供下次继续。

## 状态查看与清理

如果启用了 RC，可以使用以下接口管理 resume 状态：

- `sync/resume/status`
- `sync/resume/clear`

### 查看状态

`sync/resume/status` 可用于查看当前 copy resume 任务的状态，包括：

- job ID
- 是否存在状态
- 当前扫描状态
- 累计统计
- 最近历史
- 失败文件列表

### 清理状态

`sync/resume/clear` 可用于清除某个 copy 任务的 resume 状态。

适合以下场景：

- 任务已经确认完成，不再需要保留状态
- 想丢弃历史状态，重新开始一次新的 copy

## 使用建议

- 长时间、大批量 copy 任务建议开启 `--resume`
- 如果希望明确区分任务，建议显式指定 `--resume-id`
- 如果对失败数量有控制要求，建议设置 `--resume-error-limit`
- 如果任务已确认完成，可以使用清理接口删除历史状态

## 一句话总结

Resume V1 的定位是：

**只支持 `copy` 的文件级断点续跑。**

它会记住扫描位置、已完成文件、迁移统计和失败记录，让任务在中断后继续执行；但它不会做全量重启校验，也不会做单个大文件的内容级断点续传。
